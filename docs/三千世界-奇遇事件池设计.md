## 一、设计原则

1. **引擎与内容分离**：触发/筛选/结算逻辑在通用引擎 `systems/events.js`，事件词条是内容包 `worlds/{worldId}/events.js`——换世界只换词条和文案，引擎不动（对标天赋池的两层结构）。
2. **三种事件类型**：
   - `positive` 好事：直接给收益；
   - `negative` 祸事：直接给损失（幅度温和，放置游戏不做挫败感过强的惩罚）；
   - `choice` **选择事件**：弹出 2 个分支选项，分支带 **善恶分（karmaScore）**——这是修仙世界善恶系统的核心来源之一，也是「有选择的奇遇」决策的落地。
3. **正负偏向由 `eventLuck` 驱动**：天赋/未来系统提供的 `eventLuck` 不改变触发频率（频率归 `eventRate`），只改变正/负/选择的抽取偏向，两个乘区职责清晰不重叠。
4. **防刷屏**：同一事件有独立冷却；`once: true` 的事件一生只出一次（用于剧情向彩蛋）；连续两次触发不出同一事件。
5. **结算全部走 `mutate`**：事件效果与玩家手动操作同一条读改写通道，离线批量结算中同样可触发（见 §四）。

## 二、数据结构

```js
// worlds/xiuxian/events.js 中的单条事件
{
  id: 'cave_find',
  name: '洞府奇遇',
  world: 'xiuxian',                 // 'common' | 'xiuxian' | …
  kind: 'positive',                 // 'positive' | 'negative' | 'choice'
  weight: 8,                        // 同 kind 池内抽取权重
  once: false,                      // true = 每个存档只触发一次
  cooldownHours: 24,                // 同一事件再次触发的最小间隔
  conditions: {                     // 条件筛选（全部满足才进池）
    realmMin: 1, realmMax: null,    // 境界区间（索引）
    zoneMin: null,                  // 最低已解锁战斗区域
    minKarma: null, maxKarma: null  // 善恶值门槛（修仙专属事件可用）
  },
  text: '你在山涧旁发现一处前人遗留的洞府……',
  outcomes: [                       // 非 choice 事件：抽一条结算
    { weight: 6, effects: { stones: 120 }, log: '得了 {n} 灵石' },
    { weight: 3, effects: { qiPct: 0.10 }, log: '灵气 +10%' },
    { weight: 1, effects: { dropGear: { tierMin: 2 } }, log: '拾得一件上品法宝' }
  ],
  choices: null                     // choice 事件见下
}
```

### choice 事件结构

```js
{
  id: 'demon_at_crossroad',
  name: '岔路妖踪',
  kind: 'choice',
  conditions: { realmMin: 2 },
  text: '一名散修被妖兽围困，向你高声求救。他怀中鼓囊囊的储物袋颇为显眼……',
  choices: [
    {
      label: '出手相救',
      effects: { stones: 80 },      // 可选：附带资源结算
      karmaScore: +15,              // 写入历史事件分（正道）
      log: '你斩妖救人，散修以灵石相谢'
    },
    {
      label: '趁火打劫',
      effects: { stones: 260, qiPct: -0.05 },
      karmaScore: -20,              // 魔道
      log: '你夺了储物袋扬长而去，道心蒙尘'
    }
  ]
}
```

### 属性判定扩展（G12 · v1.2 新增）

`outcomes` / `choices` 的任意条目支持可选 `check` 字段，接入角色属性判定（精/气/神，机制与难度系数见《角色属性设计》§四）：

```
check: { attr: 'jing', dc: '中等', onSuccess: {…效果+log}, onFail: {…效果+log} }
```

- 无 `check` 的存量词条零改动兼容；首批改造 4 条 + 新增 2 条（完整词条表见 [`玄幻修仙/精气神属性实现.md`](./玄幻修仙/精气神属性实现.md) §五），扩容批在 28 条选择事件中再挂 12 条判定——修仙专属带判定词条合计 18 条 ≈ 专属池 81 条的 22.2%（全量表见 [`玄幻修仙/专属事件池（81条）.md`](./玄幻修仙/专属事件池（81条）.md)）；
- **善行判定守则**：选择分支的 `karmaScore` 不受判定成败影响（义挙不因力竭打折），判定只影响物质收益；
- 判定失败效果遵守祸事幅度守则（≤15% 资源、≤24h debuff）；
- 离线结算命中带 `check` 的事件：按当前属性正常掷判（不用「自动选善分支」的免判特权——离线自动选择规则只作用于分支选择，不作用于判定本身）；
- 带 check 词条占比目标 ≈ 事件池 1/4，防「事事掷骰」疲劳。

### 效果字段字典（事件专用，在天赋乘区字典基础上扩展）

| 字段 | 含义 | 备注 |
|---|---|---|
| `qi` / `stones` | 即时增减主资源/货币 | 负值=损失；`qiPct` 按当前灵气百分比增减。**缩放规则（复核修订）**：词条表中灵石绝对值为练气期基准值，实际结算 ×(1 + 境界索引)³——早期事件是 10 分钟级收入、真仙期约 1~2 分钟收入，后期事件的核心价值是 buff/karma 而非灵石 |
| `qiPct` | 按当前 `qi` 的百分比增减 | 祸事损失统一用它，避免大额绝对值破坏节奏 |
| `dropGear` | 直接发一件装备 | `{ tierMin }` 指定最低品阶，走 G4 自动择优 |
| `buff` | 限时增益/减益 | `{ field: 'qiRate', mult: 0.2, hours: 4 }`，存入 `worlds.*.buffs[]`，`claim` 时过期清理 |
| `karmaScore` | 善恶历史事件分 | 仅 choice 分支使用，见 §五 |
| `tribNext` | 下次渡劫成功率一次性修正 | `{ mod: +0.10 }`，用后即清（如「高人护法」） |

## 三、触发机制

```
每次 claim（在线 tick 或离线结算）：
1. p = BASE_CHANCE × dt小时数 × (1 + Σ eventRate)     // BASE_CHANCE ≈ 0.10/小时
2. 未命中 → 结束；命中 → 决定 kind：
   基线权重 positive:45 / negative:35 / choice:20
   eventLuck 修正：luck>0 → positive 权重 +luck×100，negative 权重 -luck×60
                   luck<0 → 反向（下限 5，防止某类被抽空）
3. 组池：common 池 + 当前世界池，过滤 conditions / 冷却中 / 已触发过的 once 事件，
   且排除上一条触发的事件 id
4. 按 weight 加权抽一条：
   - positive / negative → 抽 outcomes 结算，写 log
   - choice → 在线时弹选择框（挂起，不进 log）；离线结算中命中 choice 时
     **自动选 karmaScore 较高的分支**（离线不惩罚玩家，宁给善缘）
5. 记录触发时间 → worlds.{id}.eventCooldowns[eventId] = now
```

- **存档字段**：`worlds.{id}` 新增 `buffs: []`、`eventCooldowns: {}`、`eventHistory: { lastId, seenOnce: [] }`（纳入 normalize 缺省补齐）；
- **在线 UI**：非 choice 事件走浮动 toast + 事件日志栏；choice 事件弹模态框，**必须选择才关闭**（无倒计时、不自动选，放置挂机不被打断）。

## 四、离线结算中的事件

- 离线 `while (t < now && iter < 64)` 循环内，每轮迭代按该轮 dt 走一次 §三 流程，但设 **离线上限：每次 claim 最多结算 3 条事件**（防止长离线刷屏式补发）；
- 超出上限的命中直接丢弃（不补），日志只记实际结算的；
- choice 事件离线自动选高分善分支（见 §三第 4 步）；
- `buff.hours` 按离线时长正常流逝——离线 8 小时吃到的 4 小时 buff，只剩 0 小时，结算时直接过期，**不给补偿**（规则简单可预期）。

## 五、与善恶系统的衔接

karma 采用 **覆盖式重算**（主文档 §6.2 已定），事件贡献的是「历史事件分」：

```js
// 每次变更后重算，不用 += 增量
karma = clamp(
  Σ 功法.alignment分(Lv×±2)
+ Σ 装备.alignment分(件×±15)
+ worlds.{id}.karmaEventScore        // ← 本设计新增的累计字段
, -1000, +1000)
```

- 新增存档字段 `worlds.{id}.karmaEventScore`（整数，初始 0）：choice 事件选定分支时 `+= karmaScore`，**只增不清**（历史行为永久留痕，装备功法可以换、做过的事赖不掉——这是善恶系统的世界观表达）；
- 事件贡献分建议幅度：单次 ±10 ~ ±25，约为「一件正道法宝（+15）」的量级——让选择事件有存在感，但不至于单条事件扭转阵营；
- 部分修仙事件可加 `minKarma / maxKarma` 门槛，做出 **阵营反馈**：如 karma ≤ -200 才会遇到「魔道密使」，karma ≥ +200 才会遇到「仙门点化」。

## 七、日志与 UI 约定

- 所有结算事件写入 `worlds.{id}.log`（复用现有日志通道），格式：`[奇遇] 洞府奇遇：得了 120 灵石`；
- choice 事件选择后同样入 log，并追加善恶标记：`[奇遇][+15 善] 岔路妖踪：你斩妖救人……`；
- 事件日志栏最多保留 50 条（沿用现有 log 截断规则）；
- choice 模态框显示：事件名 + 正文 + 两个按钮（按钮文案 = `choices[].label`，**不预告 karmaScore 数值**，只显示分支的即时收益——善恶后果留给玩家自己体会，首次选择后可在结果页揭示 karma 变化）。

## 八、扩展新世界时的接入清单

1. 新建 `worlds/{worldId}/events.js`，导出 `{ positive, negative, choice }` 三组；
2. 非选择事件建议 8~10 条（正:负 ≈ 5:3），choice 事件 4~6 条——**choice 是该世界「道德/阵营类专属系统」的内容载体**，没有此类系统的世界（如现代都市初期）可只做非选择事件；
3. 通用池（common）自动生效，世界池只做增量；词条文案未来走词表层 `t('event.{id}.text')`；
4. 数值缩放：`stones`/`qi` 绝对值需按世界初始参数表缩放（引擎提供 `scaleByRealm(n)` 工具函数，词条里写基准值）。

## 九、平衡待办（P5 复查）

1. `BASE_CHANCE = 0.10/小时` 意味着日均 2~3 条事件，结合天赋「福缘深厚」`eventRate +25%` 后日均 3~4 条——上线后按玩家日志留存核对是否过密；
2. choice 事件的 karmaScore 幅度（±10~30）与功法/装备来源（Lv×2、件×15）的相对权重需要整体拉表复核：目标是 **前期事件主导 karma、后期装备功法主导 karma**；
