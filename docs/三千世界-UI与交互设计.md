## 一、Surface 与状态机

扩展有两个 surface（manifest `surfaces: ["module", "view"]`）：

| Surface | 用途 | 尺寸约定（x-hub 平台规范） |
|---|---|---|
| module | 宿主工作台常驻摘要卡 | 工作台**网格格子**（默认 min 2×2 / ideal 4×3）；视口=卡片内容区，**最矮可到 ~86px**，禁止假设固定像素尺寸、禁止写死 min-height；宿主已给卡片套玻璃底，页面保持透明 |
| view | 完整游戏界面 | 主工作区整页，移动端竖屏优先自适应 |

### 1.1 view 状态机

```
LOADING（boot 模式：await 读档 + normalize 完成后才首绘——宿主存储是异步桥，禁止顶层同步读）
   │
   ├─ 无存档 ──► CREATION_1 起名 ──► CREATION_2 天赋 ──► CREATION_3 选世界 ──► MAIN
   │                                      ▲______重抽（无限次）______│
   └─ 有存档 ──► MAIN

MAIN 之上可叠加的模态层（实装为单一 #modal 容器 + #trib 结果层 + #toast）：
   TOAST（拾得/入门/替换等浮动提示，3 秒自动消失，不打断）
   EVENT_CHOICE（选择奇遇模态，必须选择才关闭）
   TRIBULATION_CONFIRM（渡劫二次确认：点「渡劫突破」后弹出，显示下一境界与成功率）
   TRIBULATION_RESULT（#trib 全屏结果层：成功金光 / 失败红闪）
   TALENT_PICK（天道垂青：渡劫成功后三选一天赋）
   CONFIRM（通用二次确认：锁定天赋 / 重置存档等）
   HELP（玩法说明浮层）
```

- 创角三屏之间可 **回退**（返回上一屏修改），但未点最终「入世」前不写存档；
- 「入世」（CREATION_3 的确认按钮）一次性写入 profile + 初始化 worlds[worldId] + 生成 worldName，随后直接进 MAIN，无过场加载；
- **渡劫为确认制**（v0.3.0）：修为攒满后 `btn-break` 变为可点，**玩家亲自确认**才掷判——不存在自动触发。

## 二、创角三屏细则

### 屏 1 · 起名

| 元素 | 规则 |
|---|---|
| 标题 | 「道名初定」 |
| 输入框 | 1 个，占位符「请输入角色名」 |
| 校验 | 2~8 个字符；过滤首尾空格；空/超长时确认按钮置灰并提示 |
| 随机名按钮 | 「掷杯问名」：从修仙名字池随机（姓氏池 × 名池，如 叶/林/苏/顾/楚 × 长风/清羽/无涯/听雪） |
| 确认按钮 | 「下一步：观天赋」 |

### 屏 2 · 天赋

布局与规则以《天赋池设计文档 §七》为准，此处补充屏幕级结构：

```
┌────────────────────────────┐
│  天命所赋（2 正 1 负）        │ ← 组合类型角标
│ ┌──────┐ ┌──────┐ ┌──────┐ │
│ │ 正面卡 │ │ 正面卡 │ │ 负面卡 │ │ ← 稀有词条加描边角标
│ └──────┘ └──────┘ └──────┘ │
│  [重抽天命]      [确认锁定]   │
└────────────────────────────┘
```

- 「确认锁定」触发 CONFIRM 模态：「天赋确认后此生不可更改，是否入定？」；
- 单正单负组合时正面卡追加「极致单一 · 效果增强」角标（解释 ×1.5）。

### 屏 3 · 选世界

```
┌────────────────────────────┐
│  三千世界 · 择界重生          │
│ ┌────────────────────────┐ │
│ │ 青云界        [首发]     │ │ ← live：随机世界名 + 状态角标
│ │ 玄幻修仙 · 灵气/秘境/渡劫  │ │ ← 关键词标签（registry.tags，硬编码）
│ └────────────────────────┘ │
│ ┌────────────────────────┐ │
│ │ ？？？        [待开启]   │ │ ← coming：灰显，名字不剧透
│ └────────────────────────┘ │
│      [ 入世 · 开始修行 ]     │
└────────────────────────────┘
```

- 只展示 `visibleWorlds()`（hidden 的克苏鲁完全不出现）；
- `coming` 世界灰显、不可选，卡片文案「此界尚在混沌，未可投生」；
- live 世界卡显示 **已生成的随机世界名**（本档只生成一次并固定，与 profile.worldName 同源）；
- 首发阶段只有一张 live 卡，仍按列表布局（为未来多世界留结构）。
- ⚠️ 世界卡关键词标签来自 `registry.tags`（当前为硬编码 `['灵气','秘境','渡劫']`），未经词表层，见工程规范 §八 #1。

## 三、主界面（MAIN）信息架构

### 3.1 整体布局：左侧栏 + 内容区（宽屏）/ 顶栏 + 内容区（窄屏）

**宽屏（≥ 881px）**：`body` 为横向 flex，左固定宽侧栏 `#side` + 右侧内容区 `#content`。

```
┌─────────────┬──────────────────────────────────────┐
│ 三千世界      │                                      │
│ 放置修仙·万界轮转 │                                      │
│             │                                      │
│ 叶长风        │                                      │
│ [左道][灵蕴][灵石] │            当前页内容区            │
│ [玩法]        │                                      │
│             │                                      │
│ 壹 修行        │                                      │
│ 贰 法器        │                                      │
│ 叁 法宝        │                                      │
│ 肆 坊市        │                                      │
│ 伍 日志        │                                      │
│ 陆 设置        │                                      │
│             │                                      │
│ 道可道，非常道   │                                      │
└─────────────┴──────────────────────────────────────┘
```

**窄屏（≤ 880px）**：侧栏折叠为**顶栏**——`#side` 转为横向、品牌缩为印章、导航按钮横排换行、隐藏页脚。

- 侧栏常驻：品牌区（印章「仙」+ 「三千世界 · 放置修仙·万界轮转」）、**顶栏资源条**（角色名 `tb-name`、karma 徽标 `tb-karma`、灵蕴 `tb-lingyun`、灵石 `tb-stones`）、「玩法」按钮（`btn-help` → HELP 模态）、**导航**（`#tabs`，6 项，天干序号 壹~陆）、页脚引文「道可道，非常道」；
- 导航 6 项与页：**修行(culti) / 法器(gear) / 法宝(treasure) / 坊市(shop) / 日志(log) / 设置(settings)**；
- 顶栏资源条：karma 徽标随档位换色（正 ☯金 / 魔 ☠红 / 左 ·灰），点击弹善恶详情（见 §3.6）；
- 导航切换 = `.tab` 元素的 `on` 类互斥；默认落地页 = 修行。

### 3.2 页 1 · 修行（默认落地页）

修行页由**核心区 `.core`** 与**卡片区 `.sub-grid`** 两段构成。

**核心区**（宽屏 ≥1100px 时两列网格：`status/trib` 居左列、`qi` 占右列满高；窄屏纵向堆叠）：

```
┌─ 状态 p-status ──────────┐ ┌─ 修为 p-qi ──────────────┐
│ 当前状态 [打坐修炼][秘境历练]│ │      打坐 · 吐纳           │
│ （历练时显示当前秘境 prog 条）│ │      123,456              │
└──────────────────────────┘ │   ▓▓▓▓▓▓▓▓░░░ 62%         │
┌─ 渡劫 p-trib ────────────┐ │   产出 27.4/秒（明细 ▾）    │
│ 下一境界  元婴   还需 24,999│ │   灵蕴 1,234（功法升级消耗）│
│ 渡劫预估  76%   明细 ▾     │ └──────────────────────────┘
│        [ 渡劫突破 ]        │
└──────────────────────────┘
```

- **双状态切换**（`mode-culti` / `mode-combat`）：打坐修炼（修为×2、不推进秘境）/ 秘境历练（×1、推进秘境）；切换仅改 `ws.mode`，无二次确认；
- **修为卡**：大数字 + 上限进度条 + 产出行（点「明细 ▾」展开逐项来源：base × 天赋 × 功法 × 法器 × 法宝 × buff × 阵营 × 状态 × 顿悟）；灵蕴行显示当前值与「功法升级消耗」注记；
- **渡劫卡**：下一境界名 + 还需修为 + 成功率预估（点「明细 ▾」展开 base/resist/战力/天赋/karma/法宝/一次性修正各行）；「渡劫突破」按钮 **修为未满时置灰**，文案 `渡劫突破（修为未满）`；点击 → TRIBULATION_CONFIRM；
- 修为到上限（`qiCap`）自然封顶等待确认；真仙（无下一阶）后进度条满格 + 「已臻化境」。

**卡片区 `.sub-grid`**（宽屏 ≥1100px 两列，窄屏单列）——**4 张常显卡片，可拖拽排序**：

| 卡片 | `data-card` | 内容 |
|---|---|---|
| 角色 · 属性 | `attrs` | 战力 + 精/气/神四格（`stats`），每格带小注（主战力/主修为/主心志判定） |
| 天赋 | `talents` | **紧凑标签墙**（v0.4.1）：顶部汇总行（总条数 · 正/负 · 创角/天道垂青构成）+ chip 网格（名称 + 主效果数值）+ 详情区（点 chip 切换显示该条完整 `desc`）；注「永久生效」 |
| 秘境历练 | `zones` | 秘境卡列表（解锁/进行中/剪影），点卡切换进行中秘境；底部注「瓶颈放缓、通关必掉法器、首通赠先天法宝」 |
| 功法 | `arts` | 6 修习槽（`slots`）+ 已习功法**按品阶分组折叠**（黄/玄/地/天，组头显计数）+ 待修习架（`shelf-panel`，未达要求红字缺项）；非槽内功法带「散功」、待修习条目带「弃置」（均二次确认）；注「6 槽 · 槽内生效 · 升级耗灵蕴」 |

- **天赋标签墙（v0.4.1）**：天赋随渡劫逐次累加（终局约 10~12 条），整卡竖排会把卡片区撑得极长，故改为紧凑墙——chip 内显示「名称 + 主效果（取 `effects` 中绝对值最大的一项，如 `战力 +12%`）」，`rare` 加描边、正面绿系/负面红系；排序为「正面（稀有→普通）→ 负面（稀有→普通）」；点击 chip 在下方详情区显示该条完整描述（含来源标记「天道垂青」）；
- **功法品阶分组（v0.4.1）**：已习功法按 `tier`（黄 0 / 玄 1 / 地 2 / 天 3）分组，组头 `黄字阶 · N 部` 可点击折叠（折叠态仅存内存，不落盘）；散功/弃置为**破坏性操作**，走通用 `CONFIRM` 模态（文案含返还灵石数）。
- **卡片拖拽排序**：每张卡片右上角 `⠿` 抓手（`sh-grip`），HTML5 DnD；拖动时 `.dragging` 半透明虚线框；`dragover` 按主导轴（双列判前后）实时插位；`dragend` 落位即存 `{cardOrder:[...]}` 到 UI 偏好键 `sanqian-ui-v1`（见 §3.8），下次启动 `applyCardOrder` 依序重挂；
- 秘境卡 `.zcard.on` 高亮进行中项；hover 描边强调。

## 四、module 摘要卡

```
┌────────────────────────┐
│ 三千世界 · 青云界   ☯正  │ ← 世界名 + karma 徽标（随档位换色）
│ 叶长风 · 金丹三层         │ ← 角色名 · 境界
│ 123,456                │ ← 修为（大数字）
│ ▓▓▓▓▓▓░░░              │ ← 修为上限进度条
│ 修为     灵蕴 1,234 · 灵石 12,340 │ ← 左标「修为」，右为副资源
└────────────────────────┘
```

**平台规范约束（x-hub）**：

- **透明底**：宿主已给 module 卡套玻璃卡，页面 `background: transparent`，不铺任何不透明底；默认**无宿主表头**（不声明 `moduleOptions`），卡面标题「三千世界 · 青云界」由本页自己画；
- **尺寸自适应**：`html,body { height:100% }` + `body { padding:12px; box-sizing:border-box }` + `container-type:size`，字号与间距用 `cqh`/`clamp()` 随格子缩放；格子最矮 ~86px 时降级为「世界名 + 修为进度条」极简形态（`overflow:hidden` 兜底，不写死 min-height）；
- **打开主界面**：点击卡片调宿主桥 `runtime.open('view')`（无需权限）；**禁止** `window.open` / `target="_blank"`——宿主 webview 中静默失效；
- 数据读取走一次 `claim`（module 与 view 共享同一份扩展存储），`setInterval` 每 3 秒刷新；桥调用失败时卡片显示人话错误而非空白（`读档失败：…`）；
- karma 徽标随档位换色（`☯正` / `☠魔` / `·左`）；
- 创角未完成（无 profile）时卡片显示「三千世界 · 点击开启新生」。

## 六、文案与数字格式规范

- **数字缩写**：< 10,000 原样千分位；≥ 10,000 用「万」（12.3万）；≥ 1 亿用「亿」（4.0亿）；百分比保留 1 位小数；
- **时间**：倒计时用「X时Y分」；补货/冷却 < 1 小时显示「X 分钟」；
- **文案基调**：修仙世界用半文半白短句（「天雷落下」「速速收功」），系统级提示用白话（「确认后不可更改」）——世界观文案走词表层，系统文案也走词表层但保持直白；
- **主资源显示名**：修仙世界主资源 `qi` 的 UI 显示名为「**修为**」（`view` 页与 `module` 卡均用「修为」）；⚠️ 但 `lexicon.resource.primary` 仍写「灵气」（待统一，见工程规范 §八 #1）。历史段落中的「灵气」与「修为」同义；
- **禁语**：不出现「服务器/数据/概率UP」等出戏词；概率表达用「十之七八」「渺茫」+ 精确数字并列（「成功率 76%」）。

## 七、可访问性与适配

- 最小适配宽度 320px；**侧栏（宽屏）/ 顶栏（窄屏）固定，内容区滚动**；断点 880px（侧栏折叠）、1100px（修行页核心区与卡片区转双列）；
- 品阶/阵营不用纯色传达（色弱友好）：品阶配文字角标（凡/良/上/灵/仙），阵营配符号（正 ☯ / 魔 ☠ / 左 ·）；
- 所有可点区域 ≥ 44×44px；重抽/炼化/渡劫等高频按钮放拇指热区；
- **卡片拖拽**：`⠿` 抓手可拖拽排序；宿主 webview 支持时同时保留 HTML5 DnD；拖拽顺序持久化，刷新不丢；
- 动效全部可被系统「减弱动态效果」降级为瞬时切换（宿主 webview 支持 prefers-reduced-motion 时）；
- **桥调用容错**：所有 `xhub.*` 调用包 try/catch，被拒或失败时界面显示人话提示（错误码 + 说明），不允许白屏。

## 八、视觉基调与宿主主题规范（x-hub 平台铁律）

> 原「深底水墨」方案与平台铁律冲突（**页面永远不铺不透明底**——会盖住宿主壁纸，透底态还会白底白字），已修订为「宿主主题打底 + 水墨语义强调」方案，视觉辨识度不受影响。

### 8.1 主题归属

- **深浅色归宿主管**：宿主在 `<html>` 维护 `data-xhub-theme="light|dark"`，扩展**不做自己的主题切换按钮**；
- **页面底**：`body { background: var(--xhub-page-bg, transparent) }`（无壁纸 = 宿主页面背景，有壁纸 = 透明）；
- **内容表面**：面板/卡片/弹层底一律 `var(--xhub-surface)` 玻璃令牌；按钮/输入区「井」底用 `var(--xhub-bg-card)`；
- **壁纸透底态**（`data-xhub-wallpaper-clear="1"`）：面板去白描边、只留中性落影，文字加一档黑柔光晕；
- **所有颜色写成 `var(--xhub-*, fallback)`**，并按「双声明 fallback」规范：`:root` 写浅色兜底 + `:root[data-xhub-theme="dark"]` 重写深色兜底（无宿主浏览器预览时明暗都正确）。

### 8.2 水墨 × 暗金的游戏语义层

游戏自有 design token 映射到宿主变量，仅作**小面积语义强调**，绝不当页面底色：

| 游戏 token | 映射宿主变量 | 用途 |
|---|---|---|
| `--sq-primary` | `var(--xhub-accent, 暗金兜底)` | CTA、境界名、稀有高亮 |
| `--sq-brand` | `var(--xhub-brand-soft, …)` | 标题区弱底、正道徽标底 |
| `--sq-karma-right` | `var(--xhub-yellow, 金)` | 正道光环 |
| `--sq-karma-evil` | `var(--xhub-red, 暗红)` | 魔道气息 |
| `--sq-karma-neutral` | `var(--xhub-text-3, 青灰)` | 左道 |
| 品阶色（凡/良/上/灵/仙） | 自定义 token，双声明 fallback（灰白/青绿/靛蓝/紫/金，压暗饱和度） | 装备词条、掉落 toast |
| `--sq-success` / `--sq-danger` | `var(--xhub-green)` / `var(--xhub-red)` | 渡劫成功/失败演出、正负天赋卡 |

- 水墨氛围靠 **字重/字距/留白/内联 SVG 纹样/文案** 表达，不靠自绘深色底；
- 强调色实底上的文字**按主题显式给**（亮色主题 accent 深 → 白字；暗色主题 accent 浅 → 深字）；
- 字体：系统字体栈（`system-ui, "Songti SC", SimSun, serif` 兜底链营造书卷气），**不引入外部字体文件、零 CDN**；
- icon.svg：一柄剑横贯「三」字，`stroke="currentColor"` 单色描边（随宿主品牌色/主题自适应，不写死暗金）。
