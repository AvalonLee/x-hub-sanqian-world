## 一、项目定位

从「单一修仙挂机」重构为 **「多世界放置 RPG 引擎 + 首发玄幻修仙世界」**：

- **引擎层**提供可复用的通用系统（挂机、战斗、装备、技能、商店、事件、阶位/突破等）；
- **世界观**通过 **词表包（lexicon pack）+ 专属系统插件** 接入，一个世界 = 一个内容包，不是新代码分支；
- 首发世界为 **玄幻修仙**（由现有版本改造），其后逐步扩展其他世界。

## 四、创角流程（首次进入）

**三屏分步**（已确认，塑造仪式感）：

```
[屏 1] 起名           → 1 个文本输入
   ↓
[屏 2] 随机天赋       → 1~2 正 + 1~2 负，总数 ≤ 3；创角阶段无限免费重抽，确认即锁定
   ↓
[屏 3] 选择重生世界   → 每个世界显示随机生成的世界名 + 关键词标签
   ↓
[完成] 写入 profile，创建 worlds[worldId]，进入主界面
```

### 4.1 天赋规则

合法组合（总数 ≤ 3 且正/负各 ≥ 1）：

| 组合 | 概率建议 | 说明 |
|---|---|---|
| 1 正 + 1 负 | ~40% | 极致单一，正面天赋效果更强 |
| 2 正 + 1 负 | ~35% | 主流 |
| 1 正 + 2 负 | ~25% | 高风险高回报 |

- 生成算法：`pos = rand(1,2)`，`neg = rand(1,2)`，若 `pos + neg > 3` 重抽；
- **重抽窗口只在创角阶段**：无限次免费重抽（RPG 刷初始的标准做法），点「确认」→ 写入 `profile.talents`，此后永久锁定；
- 天赋池分两层：
  - `talents/common.js`：跨世界通用（如「天资聪慧」+产出 / 「体弱多病」-战斗速度）；
  - `talents/xiuxian.js`：修仙专属（如「雷灵根」渡劫 +15% / 「凡骨」突破需求 +10%）；
- 天赋效果直接挂到通用系统的乘区上（如 `qiRate +20%`、`combatSpeed +10%`、`shopCost -15%`）；
- **具体词条清单、效果字段字典、抽取算法与平衡说明** 见子文档 [`三千世界-天赋池设计.md`](./三千世界-天赋池设计.md)（通用池正 28 + 负 22 = 50 条，修仙专属池正 40 + 负 40 = 80 条，合计 130 条）。

### 4.2 世界名生成

世界名 **固定到存档**（`profile.worldName`），只生成一次，作为这一世的身份标识。

| 世界 | 命名风格 | 样例 |
|---|---|---|
| 玄幻修仙 | {玄/青/紫/太/九/沧}{云/霄/虚/阳/冥}{界/境/天/域} | 青云界 · 太虚境 · 九霄天 |
| 古武军势 | {大/北/南/西/东}{周/燕/夏/秦}{王朝/九州/铁原} | 大周王朝 · 北疆铁原 |
| 魔法能量 | 西幻音译 | 阿卡迪亚 · 元素之环 · 艾泽兰 |
| 科技降神 | 科幻词 | 新伊甸 · 天枢星域 · 第七区 |
| 现代都市 | 中文城市名 | 滨海市 · 江城 · 临海市 |

## 五、数据模型 v1（存档）

新扩展 ID = 新存储键，**无需兼容旧档、无迁移函数**（同版本内新增字段走 `normalize` 补齐，不升 `v`）。

```js
// STORAGE_KEY = 'sanqian-state-v1'   （另有 UI 偏好键 'sanqian-ui-v1'，见工程规范 §3.6）
{
  v: 1,

  // ── 全局档案（跨世界） ──
  profile: {
    name: '',                 // 词表默认「无名」
    talents: [ { id, kind: 'positive'|'negative', effects, ... } ],  // ≤3；历史档 fx 字段由 normalize 兼容映射到 effects
    worldId: 'xiuxian',       // 首次重生所在世界
    worldName: '青云界',       // 固定，只生成一次
    createdAt: 0              // ms；>0 视为已创角
  },

  // ── 每个世界一份独立进度（互相隔离） ──
  worlds: {
    xiuxian: {
      // 挂机核心
      qi: 0, total: 0, stones: 100, lingyun: 0, realm: 0,
      mode: 'cultivate',      // 'cultivate' 打坐修炼（修为/灵蕴 ×2，不出战斗） | 'combat' 秘境历练
      // 功法（G5）
      artsKnown: ['tuna','juling'], artsLevels: {}, shelf: [],
      slots: ['tuna','juling',null,null,null,null],   // 6 修习槽，仅槽内生效
      // 战斗（G3）
      zone: 0, prog: {}, zoneClear: {}, killAcc: 0, kills: 0,
      // 法器（G4）
      gear: { weapon: item|null, treasure: item|null, armor: item|null, accessory: item|null },
      stash: [],              // 库藏阁（佩戴要求未达标暂存，容量 12 + on_stash_cap 扩容）
      // 坊市（G6）
      shop: { goods: [], feeIdx: 0, nextRestock: 0, nextDiscount: 0, blackMarket: false },
      // 事件（G7）
      buffs: [], eventCooldowns: {}, eventHistory: { lastId: null, seenOnce: [] },

      // ── 修仙专属 ──
      karma: 0,               // 善恶值（缓存值，覆盖式重算）
      karmaEventScore: 0,     // 历史事件分（只增不清）
      attrs: { jing: 0, qi: 0, shen: 0 },            // 精气神（缓存值，可重算）
      attrEventBonus: { jing: 0, qi: 0, shen: 0 },   // 事件永久属性加成（只增不清）
      tribNext: 0,            // 下次渡劫一次性修正（掷判后清空）
      nextNeedMod: 0,         // 突破需求一次性修正（高人指点等，突破时消耗）
      tribulation: { attempts: 0, success: 0, lastResult: null },
      // 法宝（灵宝，v0.4.0）
      treasures: {
        owned: [ { id, lv } | { id, stage } ],   // 后天 lv(1~5) / 先天 stage(1~3)
        slots: [null, null, null],               // 3 栏位，练气/金丹/化神解锁
        x02Bonus: 0, onlineMs: 0, x07Count: 0, karmaAccMs: 0,
        fate: 0, towerStack: 0, tribWins: 0, h10cd: 0, budouRealm: null,
      },

      lastSave: 0, log: []    // 日志 ≤200 条（v0.4.2 由 50 上调）
    }
    // 未来：guwu / magic / tech / urban …
  },

  // ── 跨世界元进度（鸿蒙层，暂只做解锁列表） ──
  meta: { unlockedWorlds: ['xiuxian'] }
}
```

- **normalize**：逐层补齐——`profile` 缺字段给默认值；`worlds.{id}` 调对应世界包 `normalize`（缺字段补齐 + 旧档自愈 + 非法引用清洗，如法宝栏内引用必须已持有）；`meta.unlockedWorlds` 缺省 = `['xiuxian']`；
- **功法 / 法器结构**：功法 item `{ id, alignment, attr, fx, special, reqs, price, srcShop }`（`artsKnown/shelf` 元素为 id，属性查世界包数据表）；法器 item `{ slot, name, tier, alignment, atk, qiBonus?, resist?, attrValue?, reqs:{realm}, special }`（`reqs` 与 `special` 生成时定格）；法宝 item `{ id, lv|stage }`（值域由数据表 `scaled` 插值）。字段全量登记见工程规范 §三；
- 旧扩展目录 `com.avalonlee.idle-xiuxian/` 归档，旧存档自然失效。

## 六、善恶系统（修仙世界专属 · 第一个世界系统）

### 6.1 核心概念

**善恶值 `karma`**：带符号整数，范围 `[-1000, +1000]`，初始 `0`。

```
karma >= +200        正道光环
-200 < karma < +200  左道（中立）
karma <= -200        魔道气息
```

（阈值 ±200 为初版试跑值，待调参）

### 6.2 善恶值来源

| 来源 | 正道加成 | 魔道加成 | 备注 |
|---|---|---|---|
| 修习功法 | 每个正道功法 Lv × `+2` | 每个魔道功法 Lv × `-2` | 覆盖式重算，不累加；仅统计**槽内**功法 |
| 装备法器 | 每件正道法器 × `+15` | 每件魔道法器 × `-15` | 同理（四槽随机装备，词表名「法器」） |
| 奇遇事件 | 有选择的奇遇（斩妖 +善 / 劫掠 -恶） | — | 事件分写入 `karmaEventScore`（只增不清）；事件池词条见 [`三千世界-奇遇事件池设计.md`](./三千世界-奇遇事件池设计.md) |
| 击杀 / 法宝被动 | — | 化血神刀 H17「每杀业力 -1」、九幽血莲 X12「每在线 1 小时业力 -2」 | 均写 `karmaEventScore` 分量，走覆盖式重算 |

> **重要**：karma 不用 `+=` 增量，而是 **每次变更后按当前「装备 + 功法 + 历史事件分」重新计算**，避免反复穿脱装备刷分。

### 6.3 三阵营对构建的影响

功法与装备均分 **正道 / 魔道 / 左道（中立）** 三阵营：

| 阵营 | 修炼速度 | 战力 | 渡劫 | 定位 |
|---|---|---|---|---|
| 正道 | 慢（倍率 ×0.9） | 均衡 | 高成功率 | 稳 |
| 左道 | 标准 | 标准 | 无修正 | 中庸 |
| 魔道 | 快（倍率 ×1.2） | 攻击高 | 低成功率 | 快但险 |

设计目标：三阵营都有可玩性，而非「正道必选」。

## 七、渡劫系统（修仙世界专属 · 终版）

### 7.1 触发时机（v0.3.0 起：用户确认制）

**挂机自动渡劫已移除**。`claim` 内修为攒满即**封顶等待**（`qi` 自然停在 `qiCap`），由玩家在修行页点「**渡劫突破**」按钮触发：

```
修为 ≥ 突破需求 → 「渡劫突破」按钮点亮 → 点击弹确认框（成功率明细 + 失败损失预估）
   → 玩家确认 → 掷判 → 成功/失败
```

- 突破需求 = `REALMS[realm+1].need × (1 + nextNeedMod) × (1 + Σ realmCost)`；`nextNeedMod`（高人指点等）在突破时消耗；
- **离线不自动渡劫**：离线期间只结算挂机产出，修为到上限即停，等玩家回来确认（避免离线爆掉渡劫机会）；
- 确认框展示 `tribulationP` 明细（base / 抗性 / 战力 / 天赋 / 业力 / 法宝 / 器物）与失败损失预估。

### 7.2 成功率公式

渡劫抗性来自三个方向：① 个人战斗力（配装富余度）；② 法器 `resist` 词条 + 特殊词条；③ 善恶系统 karmaMod。另加天赋、法宝（灵宝）、器物（tribNext）三项。

```
resistBonus = resist项 + 战力项（上限 0.35）
  resist项 = min( (Σ法器resist + 金刚质特殊词条 60) / 1200, 0.20 )
  战力项   = min( (战力 / 当前境界基础战力 − 1) × 0.15, 0.15 )
karmaMod    = karma 分段映射（见下表）
talentBonus = Σ天赋 tribBonus + 法器/功法挂点 on_trib_flat（雷纹等）
treBonus    = 法宝：X01 气运补偿（失败累积 +2%/次，上限 0.20 + 0.10×(认主阶−1)） + X03 塔身积威（上限 0.15）
nextBonus   = tribNext（破障丹 / 吃一堑 / 养魂木等，掷判后清空）

p = clamp( base(realm) + resistBonus + talentBonus + karmaMod + treBonus + nextBonus, 0.05, 0.95 )

base(realm) = 0.95 → 0.45 线性递减（练气 0.95，真仙 0.45）
```

> 复核修订（详见《数值复核报告》问题 4）：早期草案的 `战力/50` 项会随境界 ×3 增长、自化神起裸战力即封顶 0.35，导致 resist 词条失效。修订为「resist 固定区间项 + 配装富余度项」双封顶结构，保留「战力 + 法器抗性」双来源的既定决策。

| karma 区间 | karmaMod |
|---|---|
| `>= +800` | `+0.20` |
| `+200 ~ +800` | `+0.10` |
| `-200 ~ +200` | `0` |
| `-200 ~ -800` | `-0.12` |
| `<= -800` | `-0.25` |

### 7.3 结果

| 结果 | 效果 | 日志示例 |
|---|---|---|
| 成功 | `realm + 1`，`qi = 0`，**功法等级与槽位全部保留**（不重修）；触发「**天道垂青**」三选一正面天赋（排除已有、永久生效、标记 `src='gift'`）；法宝状态复位（气运/塔身清零、认主胜场 +1）；渡劫至真仙额外赠 X01 鸿蒙紫气 | 「渡劫成功，境界晋升为「X」！天道垂青，有天赋可择」 |
| 失败 | `qi *= (1 − 损失系数)`（基准半损 0.5，天赋与「神」属性各 ±0.10，金钟罩/不动明王 -0.05/-0.08，总 clamp 30%~70%；玄黄宝塔 X03 固定 30%；补天五色石 X09 每境界一次损失减半且不计 attempts），境界不变，`lastResult='fail'` | 「天雷落下，渡劫失败，修为受损 -N（成功率 P%）」 |

> v0.3.0 变更：成功不再清零功法等级（旧设计「渡劫成功功法清零重修」已废弃），改为「天道垂青」三选一天赋作为正反馈。

### 7.4 冷却

**无显式冷却字段**：失败后修为受损、自然跌回阈值以下，重新攒气的时间就是天然冷却。确认制下玩家也可主动选择在成功率更高时再突破。

### 7.5 离线结算

- 离线只结算挂机产出（含灵蕴）、事件（单次 claim ≤3 条）、商店补货；**不掷渡劫**（确认制）；
- `iter` 上限 64 兜底，防止极端时间差导致死循环（防改系统时间作弊面）；
- 离线汇总日志：「闭关 X 小时 Y 分，得修为 N」。

### 7.6 装备词条与品阶

`resist`（渡劫抗性）为 **独立第三词条**，品阶越高词条越满：

- 凡品：`atk`
- 良品：`atk + qiBonus`
- 上品及以上：`atk + qiBonus + resist`（灵品起再 + `attrValue` 第四词条）

**佩戴要求与特殊词条（v1.4 新增）**：上品起携带佩戴境界要求（上 2 / 灵 4 / 仙 6，极品词条再 +1 阶）；上品起低概率（3%/8%/15%）随机附带 1 条特殊词条（含「无视佩戴要求」），未达标装备入库藏阁等待境界提升。完整规则见数值详设 §3.5/§3.6。

## 七·补、法宝（灵宝）系统（修仙世界专属 · v0.4.0 新增）

> 实装于 [`assets/worlds/xiuxian/treasures.js`](../assets/worlds/xiuxian/treasures.js)，数值/规则事实源为 [`玄幻修仙/法宝全录（30件）.md`](./玄幻修仙/法宝全录（30件）.md)。

### 7b.1 定位：与「法器」正交的第二装备线

「**法宝**」一词原指四槽随机装备，v0.4.0 起让位——四槽随机装备统一称「**法器**」（G4），「**法宝（灵宝）**」为独立收集系统：

| 维度 | 法器（G4，`ws.gear`） | 法宝（灵宝，`ws.treasures`） |
|---|---|---|
| 来源 | 战斗掉落 / 坊市 / 炼化，随机生成 | 首通秘境 / 渡劫奖励 / 坊市绝版 / 黑市，**固定 30 件** |
| 槽位 | 4 槽（兵刃/宝珠/甲衣/佩饰） | **3 栏位**（练气 0 / 金丹 2 / 化神 4 解锁） |
| 词条 | `atk / qiBonus / resist / attrValue` + 特殊词条 | **无 atk/resist**，只有签名效果（乘区加算 + 挂点加算） |
| 成长 | 无（生成即定格，可炼化） | **先天 12 件**认主 1~3 阶 / **后天 18 件**祭炼 1~5 级 |
| 唯一性 | 可重复获得 | **全局唯一**，已持有不重复给 |

### 7b.2 数据与成长

```js
// 存档：ws.treasures
{ owned: [ {id:'h01', lv:1} | {id:'x01', stage:1} ], slots: [null,null,null],
  x02Bonus, onlineMs, x07Count, karmaAccMs, fate, towerStack, tribWins, h10cd, budouRealm }

// 数据表：scaled 值域 [v1, vmax]
//   后天 kind:'hou'：按祭炼等级 lv(1..5) 线性插值   frac = (lv-1)/4
//   先天 kind:'xian'：按认主阶 stage(1..3) 线性插值  frac = (stage-1)/2
//   键前缀：'mult:xxx' → 乘区加算；'hook:xxx' → 挂点加算
```

- **祭炼（后天）**：`refineCost = round(400 × 2.2^(lv−1) × (1 + realm×0.4))` 灵石，lv 5 封顶；
- **认主（先天）**：每阶需累计 **2 次渡劫成功**（全局计数 `tribWins`），阶数越高签名效果越强；
- **获得唯一入口** `grant(ws, id)`：重复持有返回 false；先天落 `{stage:1}`、后天落 `{lv:1}`；
- **佩戴校验** `meetsReq`：只读当前值（境界 / 精气神 / karma 上下限），穿脱法器/功法即时影响达标——所以可「临时换装」满足要求。

### 7b.3 签名效果（按机制分类）

| 类别 | 法宝示例 | 机制 |

### 7b.4 与渡劫的衔接

- x01 鸿蒙紫气：渡劫失败累积 `fate`，下次成功率 +2%/次（上限 `0.20 + 0.10×(认主阶−1)`），成功清零；

- 渡劫成功 `tribWins + 1`（推进先天认主）；渡劫至真仙额外赠 x01。

- **不引入构建工具、零 CDN**：所有 `*.js` 为 IIFE，挂 `window.SQ.*`，HTML 里按依赖顺序 `<script src>` 加载（静态 HTML + 本地相对路径是平台推荐形态）；**禁止引用任何外链资源**（Tailwind CDN / Font Awesome / Google Fonts 会被宿主 CSP/离线拦掉），图标用内联 SVG；
- **桥 API 由宿主注入**：直接调 `window.xhub.*`，不 import 任何 xhub 包；能力存在性以运行期 `runtime.info().capabilities` 为准；
- `manifest.json` 关键字段：`id: "com.avalonlee.sanqian-world"`（自有反向域名，非平台保留段）、`name: "三千世界"`、`version: "0.4.0"`（必须三段纯数字）、`runtime: "web"`、`kind: "view"`、`surfaces: ["module", "view"]`、`openIn: ["view"]`、`entry`（module/view 各指向真实 HTML 文件）、`icon`、`description`、`permissions: []`；
- **权限零声明的依据**：本扩展只用 `storage.*` / `runtime.open` / `events.on` / `theme.*` / `config.*`——全部无需权限；不用 `data.*` / `fs` / `openExternal` / `events.emit`。⚠️ 平台发布预检对源码做**纯文本静态扫描**（注释里出现 `xhub.data.xxx` 调用示例也算「用到」），代码与注释中不得出现未声明权限的 API 字样；
- **存储契约**：`xhub.storage` 是**异步 Promise** 且按扩展隔离、跨形态（module/view）共享同一份——core 的 `load/save/claim/mutate` 全链路必须 async，入口用 **boot 模式**（先 `await` 读档再首绘，禁止顶层同步读）；`localStorage` 回退仅用于无宿主浏览器预览（`typeof window.xhub === 'undefined'` 时）；
- **主题铁律**：页面永远不铺不透明底——`body` 底用 `var(--xhub-page-bg, transparent)`，内容表面用 `var(--xhub-surface)` 玻璃令牌，所有颜色写成 `var(--xhub-*, fallback)` 并按「双声明 fallback」适配明暗（详见 UI 文档 §八）；
- 核心运行时接口：`window.SQ = { KEY, H, Worlds, register, visibleWorlds, getPack, defaultState, normalize, created, enterWorld, load, save, claim, mutate, bindPagehideSave, generateWorldName, SQS }`（`load/save/claim/mutate` 返回 Promise；工具函数挂 `window.SQH`，子系统挂 `window.SQS`）；
- **世界包契约**：世界包经 `SQ.register(pack)` 注入——元数据（`id/displayName/status/tags/nameParts/lexicon`）、数据表（`realms/zones/gearTiers/gearSlots/salvageBase/gearSpecials/specialPool/arts/pills/attributes/events`）、钩子函数（`gearName/alignmentQiMult/recalcDerived/rollTribulation/tribulationP/karmaTier`）与生命周期三函数 `initialState()` / `normalize(raw)` / `claim(s, ws, dt, now, res)`；契约自查表见工程规范 §二。
- **真机调试**：扩展中心 →「我的扩展」→ 添加源码目录（含 manifest.json）即加载，改代码约 1.5s 自动热重载；module 形态需到「工作台 → 自定义布局」拖入网格。
