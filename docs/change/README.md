|---|---|

## 一、目录与命名

- 目录：`docs/change/`
- 日志文件：`YYYY-MM-DD.md`（**本地时区 Asia/Shanghai**，月/日零填充，如 `2026-09-28.md`）
- 规范说明：本 `README.md`（不放日志内容）
- 一天一个文件；不建子目录、不按周/月分卷。

## 二、归档口径（何时追加、何时新建）

1. **按完成时刻归档**：以变更**落盘完成**的时刻所在日为准。
2. **同日追加**：同一自然日的所有变更，按时间先后**追加**进当日文件，条目按 `## HH:MM` 递增。
3. **隔日新建**：跨过 00:00 后的新变更，写入新一天的文件。
4. **跨天变更**：一次变更从第 N 天持续到第 N+1 天，**归入完成当日（第 N+1 天）**。若已在第 N 天写了草稿条目，则在第 N+1 天落定，并在第 N 天该条目下追加一行 `→ 续见 YYYY-MM-DD.md`。
5. **补记**：事后才发现的未登记变更，写入**实际发生日**的文件；条目头标 `[补记]`，时间不可考时用 `## --:--（补记）`。实际发生日的文件不存在则新建。
6. **记录边界**：
   - **要记**：凡**落盘**进本扩展目录的文件改动（含本日志自身、文档版本号、文件名改动、删除）。
   - **不记**：只读排查、未落盘的试验、临时草稿（`.workbuddy/tmp/` 等仓库外文件）；但若排查得出影响设计/数值的结论，该结论落到正式文档时，随该文档改动一起记。
   - 一次「意图」最终没落盘 → 不记；落盘后又撤掉 → 记两条（原变更 + 回退）。

## 三、追加语义（append-only）

- 已写入的条目**永不改写**，只允许追加。
- 旧条目写错：**不动原条目**，在其下方追加 `> 勘误（YYYY-MM-DD HH:MM）：…`。
- 回退某次变更：**不删原条目**，追加一条「回退」类型条目，注明被回退的条目与回退后状态。

## 四、条目模板（必填字段）

```markdown
## HH:MM · <类型> · <一句话标题>

- **范围**：通用引擎 / 修仙 / 古武 / docs / 平台配置
- **摘要**：为什么改 + 改了什么（不看代码也能看懂）
- **变更文件**：

  | 文件 | 变更前 | 变更后 |
  |---|---|---|
  | `docs/三千世界-xxx.md` | v1.4 | v1.5 |
  | `assets/worlds/xiuxian/events.js` | 头注释引「80 条」 | 引「81 条」 |

- **回退指引**：可直接执行的回退动作（见 §五）
- **验证**：如何确认没坏（冒烟项编号 / 自检命令 / 人工检查点）
- **关联**：工程规范 §八 偏差登记 #N / `DESIGN-ADDENDUM.md` §x / 本日前一条目
```

- **类型**取值：`新增` / `修改` / `修复` / `重构` / `文档` / `数值` / `配置` / `删除` / `回退`。
- 单条只讲**一件事**；一次变更触及多系统时可拆多条，但须互相用「关联」串起。

## 五、回退规范（本规范的核心目的）

- **首选版本控制**：若扩展目录已纳入 git，条目须记录 `commit` 短哈希与回退命令（如 `git revert <hash>` / `git checkout <hash> -- <path>`）。
- **当前现状**：`extensions/com.avalonlee.sanqian-world/` **尚未纳入 git**（父工作区 git 存在 PortableGit 引用缺陷，见 `HANDOVER.md` §三）。因此本阶段**条目内必须自带「可复原信息」**：
  - 文件**重命名/删除** → 写明**原路径**；
  - 数值/文案改动 → 写明**原值或原段落**；
  - 大段改写 → 写明**原版本号**，必要时把原文另存一份（路径写进条目）。
- **回退粒度**：
  - 条目级 —— 只回退某一条；
  - 文件级 —— 回退某日全部条目（按当日文件倒序逐条还原）。
- **回退后必须追加**一条「回退」类型条目，记录回退了什么、回退到哪个状态、谁在何时执行。

## 六、与其他记录的关系（避免重复与冲突）

| 记录 | 定位 | 与本次日志的关系 |
|---|---|---|
| `docs/change/YYYY-MM-DD.md` | **逐次变动的时间线**（本规范） | 变更的**权威记录** |
| 工程规范 §八 偏差登记 | **长期**「文档 ↔ 实装」偏差清单（带状态：待办/已校正/接受） | 本条日志发现的偏差在此挂账；消项时两边互相引用 |
| `DESIGN-ADDENDUM.md` | v0.2.0~v0.4.0 的历史台账（**已合回**，仅溯源） | 新变更**不再**写这里 |
| 各文档 `| 版本 |` 行 | 文档自身的版本号 | **任何版本号变更必须在当日日志留条目** |
| `.workbuddy/memory/`（工作区，**仓库外**） | 助手工作日志，非交付物 | 变更以 `docs/change/` 为准 |

## 七、自查清单（每次变更收尾前逐条过）

- [ ] 当日文件存在，路径与命名符合 §一
- [ ] 条目按时间**追加**，未改写旧条目
- [ ] 「变更文件」表逐文件列全，含版本号/条数/文件名等前后值
- [ ] 「回退指引」可直接执行（无 git 时已给可复原信息）
- [ ] 文档版本号、工程规范 §八 偏差登记已同步
- [ ] 跨天 / 补记已按 §二 归档
