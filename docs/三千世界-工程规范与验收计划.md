## 一、词表层规范（G11）

### 1.1 取词规则

> **目标形态（P3 待落地）**：所有面向玩家的文案 **一律走 `t(key)`**，源码中不允许出现裸中文常量（日志模板、按钮、标题、词条名、事件文案全覆盖）；词表按 `profile.worldId` 加载：`common` 基础词表 + 世界词表覆盖（世界词表缺 key 时回落到 common，common 也缺时 **直接显示 key 本身**——让遗漏在界面上肉眼可见，而不是静默空白）；词条支持插值占位，如 `log.tribulation.success = "渡劫成功，境界晋升为 {realm}"`，占位符统一 `{snake_case}`。
>
> **实装现状（v0.4.0）**：**无**独立 `lexicon/{world}.js`、**无** `t(key)` 函数、**无** `common` 分层与插值机制。词表以 `lexicon` **对象内联**于世界包（`assets/worlds/xiuxian/index.js` 的 `SQ.register({…})` 内），view 经 `L()` 访问器读取（`view/index.html:393`），且**仅覆盖 10 个体系名**；UI 主文案（修为/灵气/法器/境界/渡劫/坊市等，view 内 100+ 处中文常量）**仍为硬编码**。本节 1.2/1.3 为**目标规范**，实际落地程度见 §八 偏差登记 #1。

### 1.2 key 命名规范（目标）

```
{domain}.{item}[.{sub}]     全小写 snake_case，层级 ≤ 3
```

| domain | 覆盖内容 | 示例 key |
|---|---|---|
| `resource` | 主资源、货币、战力等数值名 | `resource.primary`（修为）/ `resource.currency`（灵石） |
| `realm` | 阶位体系名 + 各阶位名 | `realm.system`（境界）/ `realm.3`（元婴） |
| `idle` | 挂机动作与状态文案 | `idle.action`（打坐）/ `idle.cap_full` |
| `combat` | 战斗区域体系 + 各区名 + 瓶颈提示 | `combat.system`（秘境）/ `combat.zone.1` / `combat.bottleneck` |
| `gear` | 装备体系名、槽位名、品阶名 | `gear.system`（法器）/ `gear.slot.weapon` / `gear.tier.4`（灵品） |
| `skill` | 技能体系名 + 各功法名与描述 | `skill.system`（功法）/ `skill.tuna.name` |
| `shop` | 商店体系名、按钮、黑市 | `shop.system`（坊市）/ `shop.refresh` / `shop.blackmarket` |
| `event` | 事件名 / 正文 / 分支文案 / 日志 | `event.cave_find.name` / `event.cave_find.text` / `event.cave_find.choice_a` |
| `talent` | 天赋名与描述 | `talent.gifted.name` / `talent.gifted.desc` |
| `tribulation` | 渡劫演出与日志文案 | `tribulation.start` / `tribulation.fail` |
| `karma` | 善恶档位名与详情文案 | `karma.tier.right`（正道光环） |
| `ui` | 通用按钮、确认框、格式文案 | `ui.confirm` / `ui.cancel` / `ui.number.wan` |
| `world` | 世界显示名、状态角标、关键词标签 | `world.xiuxian.name` / `world.status.coming` |

> **命名勘误（v0.4.0）**：装备体系名现为「**法器**」（四槽随机装备），「**法宝（灵宝）**」是 v0.4.0 新增的独立收集系统（`ws.treasures`，30 件固定）——二者正交，`gear.system` 指前者。主资源内部字段 `qi`，修仙世界 **UI 显示名「修为」**，但实装 `lexicon.resource.primary` 当前仍写「灵气」（待统一，见 §八 #1）。

### 1.3 实装 lexicon 键一览（现状 · v0.4.0）

世界包内联 `lexicon` 对象的**全部实际键**（嵌套结构，非 flat key）：

| 键 | 现值 | 说明 |
|---|---|---|
| `resource.primary` / `resource.currency` | 灵气 / 灵石 | 主资源显示名仍为「灵气」（应为「修为」，见 §八 #1） |
| `realmSystem` / `idleAction` / `combatSystem` | 境界 / 打坐 / 秘境 | 体系名 |
| `gearSystem` / `skillSystem` / `shopSystem` / `eventSystem` | 法器 / 功法 / 坊市 / 奇遇 | 体系名 |
| `rebirth` / `breakthrough` | 转世 / 渡劫 | 动作名 |

> 世界卡标签（`tags: ['灵气','秘境','渡劫']`）为**硬编码**，未经 lexicon。

### 1.4 完整性审计（P3 验收手段）

- 审计脚本思路：扫描 `view/` 与 `assets/systems/` 源码中的 CJK 字符字面量，白名单（注释、词表文件本身）之外出现即报错；
- 每个世界包交付时跑一遍「key 对账」：词表 key 集合 ⊇ 代码引用的 key 集合，缺失清单直接输出。
- ⚠️ 该审计**当前不可通过**（view 存在大量硬编码中文，见 §1.1 现状），列为 P3 门槛。

## 二、世界注册表与世界包契约（G10）

### 2.1 registry 条目字段

| 字段 | 类型 | 说明 |

### 2.4 命名生成器规则

- 从 `nameParts` 各段独立随机拼接；生成时机 = 创角屏 3 首次渲染；
- 结果 **固定写入 `profile.worldName`**，此后所有界面只读不再生成；
- 去重不强求（名字池组合数 ≥ 300 时碰撞概率可接受），但同一次创角会话内重进屏 3 不重掷（防「刷世界名」）。

### 3.5 存储键与隔离

| 键 | 位置 | 用途 |
|---|---|---|
| `sanqian-state-v1` | `xhub.storage`（宿主内，按扩展隔离、跨形态共享） | 主存档（`core.js::KEY`） |

> 无宿主浏览器预览（`typeof window.xhub === 'undefined'`）时，主存档亦回退到 `localStorage` 同名键；宿主内**绝不**触碰 localStorage 存主存档。

### 3.6 存档纪律

- **异步桥契约（x-hub 规范）**：`xhub.storage` 是异步 Promise、按扩展隔离、跨形态（module/view）共享同一份——`load/save/claim/mutate` 全链路 async，入口用 **boot 模式**（先 `await` 读档再首绘，禁止顶层同步读）；`localStorage` 回退**仅限无宿主浏览器预览**（`typeof window.xhub === 'undefined'` 分支）；
- **单一写入通道**：一切状态变更走 `mutate(stateRef, fn)`（玩家操作）或 `claim(stateRef)`（时间结算），禁止旁路直写存储；两者均为「读最新持久态 → 变更 → 落盘 → `adopt` 回灌本地引用」；
- **`mutate` 事务性**：`fn` 抛错则**不落盘**（`core.js::mutate` try/catch 包裹）；
- **karma / attrs 是缓存**：任何影响其值的变更（换装/升级功法/事件选择/渡劫）后，`mutate` 统一回调 `SQS.recalcDerived` 覆盖式重算（防刷分）；存档里的值仅用于读取加速，以重算结果为准；
- **时间戳统一 ms**；所有「未来到期」字段（buff 到期、补货时间、冷却）存绝对时间戳，不存剩余秒数（防改系统时间刷 buff 的成本最低化，本期接受该作弊面）；
- **版本号规则**：结构变更 → `v` +1，并在 core 登记「v(n-1) → v(n) 迁移规则」；同版本内新增字段走 normalize 补齐不升版本。

## 七、平台接入规范与发布清单（x-hub）

> 依据《x-hub 扩展开发规范》（平台附件）校准，P1 起全程生效；与本文档冲突时以平台规范为准。

### 7.1 manifest 完整声明（定稿）

```json
{
  "id": "com.avalonlee.sanqian-world",
  "name": "三千世界",
  "version": "0.4.0",
  "runtime": "web",
  "kind": "view",
  "surfaces": ["module", "view"],
  "openIn": ["view"],
  "entry": {
    "module": "./module/index.html",
    "view": "./view/index.html"
  },
  "icon": "./icon.svg",
  "description": "多世界放置修仙：起名、抽天赋、择界重生，挂机渡劫证道真仙",
  "permissions": []
}
```

- `id` 为开发者自有反向域名（`com.x-hub.*` 是平台保留段，禁用）；全小写、含 `.`、≤128 字符 ✓；
- `version` 必须三段纯数字（当前 `0.4.0`），发布弹窗会自动递增补丁号写回；
- 不声明 `moduleOptions`（默认无宿主表头，卡面自绘）；不声明 `moduleVariants`（本期单形态，默认 min 2×2 / ideal 4×3，多形态留待 P2 实机评估）；
- 不声明 `network` / `data:*` / `fs` / `open-url` / `events` / `shared-storage`——本扩展只用免权限 API（`storage.*`、`runtime.info/open`、`events.on`、`theme.get`、`config.*`）。

### 7.2 开发纪律（平台易错点对策）

1. **桥由宿主注入**：直接调 `window.xhub.*`，不 import 任何包；能力可用性以运行期 `runtime.info().capabilities` 为最终权威；
2. **静态扫描是纯文本匹配**：注释、字符串、示例里出现 `xhub.data.…` / `xhub.net.…` 等未声明权限的调用字样会被判「用到没声明」直接 error——文档示例不要抄进源码注释；
3. **planned API 禁用**：`clipboard.* / net.* / system.* / ui.* / fs.readText 等受控读写` 未实现，勿依赖（`ui.toast` 不存在——游戏内 toast 全部自绘 DOM）；
4. **外链**：`window.open` / `target="_blank"` 在宿主静默失效；本扩展无外链需求，若未来加「官方群/反馈页」必须走 `openExternal` + `open-url` 权限；
5. **存储**：异步 boot 模式（§3.6）；键名 `sanqian-state-v1` 在扩展隔离空间内唯一即可；宿主自己的 `.storage.json` / `.config.json` 不要当数据目录用；
6. **web 运行时无落盘需求**：本扩展不写文件（无 service 后端、无 `.data/` 目录）；导出存档等需求未来若做，走 `fs.saveText`（需补 `fs` 权限声明）；
7. **入口 HTML**：零 CDN、零构建，本地相对路径引用 `assets/*.js`；语言 `lang="zh-CN"`；viewport 声明齐全。

### 7.3 发布上架流程（P8 前或用户要求上架时执行）

1. 客户端「发布」→ 本地预检（与 4.9 平台关卡组同口径）→ 打包 `.xhpack` 上传；
2. 平台机器关卡：包结构 / manifest / 入口文件 / 权限申报对账 / 静态扫描 / 版本递增；
3. 人工审核 → 签名上架，已装用户自动更新；
4. 截图物料：1~3 张（主界面修行页 + 创角三屏 + module 卡），单张 ≤2MB；
5. 发布者身份前置：账号登录 → 邀请码 → 申请开发者（首次发布前预留审核时间）。
